### 2. Construir uma casa

Imagine uma pessoa que recebeu um terreno e quer construir uma casa.

Ela tem duas opções.

**Primeira opção: construir do jeito tradicional.**

Ela assenta os tijolos um a um, faz a massa, corta a madeira, monta o telhado com telhas de barro cozidas em fornos de Assu. Decide a ordem das tarefas, escolhe os materiais, executa tudo com as próprias mãos.

Durante a obra, pode usar ferramentas prontas: uma furadeira, uma betoneira, um serrote. Cada ferramenta faz uma tarefa específica quando o construtor decide usar. O controle da construção continua com ele.

**Segunda opção: construir com um sistema pré-montado.**

Em vez de tijolos soltos e telhas artesanais, o proprietário compra um kit de casa pré-fabricada. Vem com painéis de parede de concreto, lajes prontas, estrutura metálica parafusada, telhado de fibrocimento fabricado em indústria, caixa d'água azul de plástico. Cada peça já vem pronta, no tamanho certo, com encaixes definidos.

O kit vem com um manual de montagem. O manual diz a sequência: primeiro fixe os pilares, depois encaixe os painéis, depois instale o telhado, depois conecte as instalações elétricas e hidráulicas nos pontos que já vêm previstos.

O construtor não decide a ordem principal da obra. Ele executa cada etapa no momento que o manual manda. Mas ele pode personalizar algumas coisas: escolher a cor das paredes, o tipo de piso, o acabamento. O sistema pré-montado tem pontos de personalização.

A diferença fundamental está em quem controla o processo. Na construção tradicional, o construtor controla o fluxo e usa ferramentas quando quiser. No sistema pré-montado, o construtor preenche as lacunas nos momentos definidos pelo manual. O controle do fluxo foi invertido: saiu das mãos do construtor e passou para o sistema construtivo.

O kit também pode vir com o canteiro de obras já preparado: a fundação pronta, o terreno nivelado, as instalações provisórias montadas. Isso reduz o trabalho inicial.

Depois que a casa fica pronta, há uma etapa diferente: colocar a casa em funcionamento. É preciso ligar a energia, a água, testar os equipamentos. Construir, preparar e funcionar são etapas relacionadas, mas distintas.

Agora imagine que o proprietário precise de mais peças depois. Ele não fabrica as peças. Ele faz um pedido para a indústria: "quero dez telhas de fibrocimento de 5 por 2". A indústria recebe o pedido, fabrica ou separa as peças e entrega. O proprietário não precisa saber como a telha é feita por dentro. Ele só precisa saber o formato do pedido e o que vai receber de volta.

Agora, os elementos da construção recebem seus nomes na computação.

### 3. Mapeamento dos conceitos

| Elemento da metáfora | Conceito de computação |
|----------------------|------------------------|
| Ferramentas (furadeira, betoneira, serrote) | Biblioteca |
| Sistema pré-montado (kit + manual) | Framework |
| Inversão de quem controla o fluxo da obra | Inversão de controle |
| Canteiro de obras já preparado | Scaffolding |
| Ligação de energia, água, equipamentos | Bootstrapping |
| Pedido feito para a indústria | API |
| Kit específico para casas naquele padrão | Spring Framework |
| Mecanismos que preparam o canteiro e ligam a casa | Spring Boot |

### 4. Biblioteca e framework

Uma **biblioteca** fornece código reutilizável para tarefas específicas. A aplicação usa a biblioteca quando precisa daquela funcionalidade e mantém o controle do fluxo. É como a furadeira: o construtor decide quando usar e ela faz apenas aquilo para o que foi projetada.

Um **framework** fornece uma estrutura mais ampla e participa da execução da aplicação. O framework organiza o fluxo e determina os momentos em que o código do programador será executado. É como o sistema pré-montado: o construtor executa as tarefas, mas a sequência e a integração são definidas pelo manual.

Sem framework:  
Aplicação → chama biblioteca → recebe resultado  
O código controla quando a biblioteca é usada.

Com framework:  
Framework → conduz a execução → chama código da aplicação → continua a execução  
O framework controla parte do fluxo.

Esse princípio é chamado de **inversão de controle**.

### 5. Scaffolding e bootstrapping

**Scaffolding** é a estrutura inicial criada para facilitar o início de um projeto. É o canteiro de obras já preparado: fundação pronta, organização básica definida, alguns elementos já montados.

**Bootstrapping** é a inicialização da aplicação e a preparação dos componentes necessários para que ela funcione. É ligar a energia, a água, os equipamentos e colocar a casa em condições de uso.

Scaffolding → criação do projeto.  
Bootstrapping → inicialização para execução.

### 6. API

Uma **API** define uma interface por meio da qual um componente ou serviço pode ser usado por outro. Na metáfora, é o pedido feito para a indústria. O proprietário faz uma solicitação seguindo regras conhecidas — "quero dez telhas de 5 por 2" — e recebe um resultado sem precisar saber como a telha é fabricada.

Uma API estabelece **como** uma funcionalidade pode ser solicitada e **quais regras** devem ser seguidas.

### 7. Por que o Spring é de graça?

O Spring é um projeto de **código aberto**. O código-fonte está disponível para qualquer pessoa usar, modificar e distribuir. Mas isso não significa que ninguém ganha dinheiro.

A empresa por trás do Spring ganha dinheiro com:

- **Suporte pago**: empresas grandes pagam por suporte especializado e contratos de manutenção.
- **Treinamento e certificação**: cursos oficiais e certificações são pagos.
- **Ferramentas complementares**: produtos e serviços em volta do Spring que são pagos.
- **Serviços gerenciados**: infraestrutura e serviços de nuvem.

O código é gratuito, mas o conhecimento especializado, o suporte e os serviços em volta dele são cobrados.

Além disso, empresas como Google, Amazon e Netflix usam o Spring. Quando encontram problemas, corrigem e enviam a correção de volta para o projeto. Isso melhora o Spring para todo mundo. Quanto mais gente usa, mais bugs são encontrados, mais melhorias são feitas, mais o projeto fica forte.

Resumindo: o Spring é gratuito porque o modelo de negócio do código aberto funciona assim — o código é livre, mas o ecossistema em volta dele gera dinheiro.

### 8. Spring

O **Spring Framework** é o framework usado para estruturar a aplicação e participar do fluxo de execução. É o sistema pré-montado completo.

O **Spring Boot** simplifica a criação, configuração e inicialização de aplicações baseadas no Spring. Prepara o canteiro e liga a energia.

Bibliotecas como Jackson, Hibernate, JUnit e o driver do PostgreSQL fornecem funcionalidades específicas. São as ferramentas.
